## 1. YOUR歳時記

- このサービスは、俳句や短歌を学習する中学生や高校生が現代社会のさまざまな場面で心動かされた季節の情景や行事、言葉を記録し、みんなで共有することで、三年間の学校生活を通して自分たちだけの「デジタル歳時記」を育てていく教育用サービスです。
- 生徒が互いの学習の取り組みを相互に確認・参照できる「場所」を作り出し、単に「見る」だけでなく「自分の学びに活かす」ための機能を打ち出すことで、協働的な学習を深めます。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

このアイデアの元になった
**自分自身の体験・感情・違和感**を教えてください。

- 中学校や高校で国語の授業を行っている時、生徒が作った作文や短歌をクラスや学年で共有するのに適したプラットフォームがなく、そうした成果が消えて参照されなくなることをもったいなく感じていました。

---

### 2-2. なぜそれが「気になった」のか

同じ体験をしても、気にしない人もいます。
**なぜ自分はそれが気になったのだと思いますか？**

- 学校における集団授業の意義は、生徒同士が互いの成果（作品、意見、課題など）を見せ合い、自分の学習を一般化することにあります。しかし、そうした機会がないと、生徒各人の学習は特殊化されたままに終わり、多面的な視点を獲得することができません。また、生徒の面白い発見が顧みられなくなることは、授業をする上でも不便であり、もしそうしたことが解決できるなら、新しい形の授業展開が可能になると考えていました。

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

その体験の中で、最初に感じた「困りごと」は何ですか？

1人の生徒が書いた俳句や短歌をクラスや学年全体で共有するために場所がなかったことです。現在では教育用クラウドサービスが普及していますが、それは掲示板や生徒の学習記録、成績管理などの汎用的な目的に沿ったものであり、「歳時記」のような用語集を統括する機能はありません。また、短歌や作文集ならば冊子の形にして学年で配布する学校はありますが、それは思い出作りの要素が強く、授業展開では使えません。

---

### 3-2. 本当に解決したい課題は何か

「なぜそれが困るのか？」を**最低3回**繰り返してください。

- 生徒同士が各自の成果を確認、参照できないと、各自の学習が「特殊化」されたままに終わるから。
- 生徒の成果を持続的に確認、参照できないから。
- 共同で一つの成果を作るという機会を作れないから。

→ 本当に解決したい課題：生徒がそれぞれの成果を持続的に参照し、自分の学習に活かすための「場所」を構築すること。そのために、誰でも扱うことができる「季語」を集めた「デジタル歳時記」を作る。

※「アプリでできそうなこと」ではなく
※「人の行動・感情の問題」になっているか確認してください。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー
中学生・高校生（エンドユーザー）、学校教員（管理者）

**注意：ターゲットは狭く絞ってください。**

年齢設定：
  - 年齢：12歳以上
  - 理由：中学生・高校生はITリテラシーが身に付く年齢で、SNSにも慣れ親しんでいます。また、中学生はタブレットの持ち帰りや家庭での利用が小学生ほど制限されていません。

生活・状況設定：
  - 生活・状況：生徒は国語の授業で自分自身の俳句や短歌を作ります。教員は国語の授業で俳句や短歌を指導します。
  - 理由：生徒が現代の生活の中で見つけた季語を共有し、全員で一つの「歳時記」を育てるという学習体験を、このアプリを使うことで実現します。

環境設定：
  - 環境：俳句や短歌を制作している時。
  - 理由：検索に優れた辞書機能と誰にも見やすく使いやすいユーザインターフェイスで、教員と生徒に「実際に使ってもらえる」仕組みを作ります。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

このサービスは、ユーザーがどのような状況・きっかけで
「使ってみよう」と思い、利用を始めるサービスでしょうか？

また、一度使って終わりではなく、
**「なぜ・どのように使い続けてもらえるのか」**
までイメージできているかを考えてみてください。

- どんな場面・困りごとがきっかけで、このサービスを知る・思い出すか：
　教員が授業で短歌や俳句を扱い、生徒に季語を使った俳句などを作るよう指導する時。
- 最初の一歩（登録・導入）で、ユーザーは何をする必要があるか：
　生徒が各自でパスワードを設定して登録します。生徒（エンドユーザー）はログインした後、自分で考えた季語を見出し語にして、意味とそれを使った俳句や短歌の作例を入力します。その後はずっと閲覧可能、登録可能な状態にします。
- 利用を続ける理由は何か？（習慣・必要性・価値）：
　教員は授業以外でも自治体や法人が主催する作文コンクールに応募する俳句や短歌を生徒に作成させる際に、参考にしたり利用させたりするほか、生徒の協働的な学習の例として他学年や学外者に紹介します。

**※ toB向けサービスの場合は、以下の点も意識してみてください（難易度が高いため、特に具体的にお願いします）**
- 企業や組織が、このサービスを導入する判断をする理由は何か：
　「生徒たちで育てるデジタル歳時記」という、従来の教育用アプリにはない価値があるからです。具体的には、それまでは紙やExcelで管理していた生徒が作った俳句・短歌と季語の対応が「デジタル歳時記」に一元化されることで、管理コストを下げることができます。また、生徒の作品が「歳時記」という形でストックされ、コンクール応募時に「過去にどんな季語を使った作品があったか」を調べやすくなるほか、翌年度以降の生徒にもこれらを参考資料として引き継げます。
　生徒にとっては、「自分の考えた季語や作品がアプリに残り、他の生徒にも見てもらえる」という達成感・承認欲求を得ることができ、学習のモチベーションの向上に繋がります。
- どうしたら機密情報や業務データを、個人開発のサービスに登録したいと思ってもらえるか：
　非公開設定もできるようログイン機能を付け、掲示板などの余計な機能は付けず管理コストを減らします。

　いかにアプリにアクセスしやすくするか、そしてこのアプリの問題意識に共感できるか、という点にあります。

### 10-2. 技術選定の比較検討

使用する技術を列挙するだけでなく、**なぜその技術を選んだのか**を比較して書いてください。

- 他にどんな技術を候補にしたか
- なぜその候補ではなく、この技術を選んだのか
- 不採用にした技術とその理由

| 候補 | 採用/不採用 | 理由 |
| Ruby on Rails | 採用 | DBと連携した辞書アプリを作成するのに過不足ないから |
| React | 不採用 | 学習期間が短く、卒業制作の期間内でのリリースが難しいと判断 |
| Ransack | 採用 | 検索機能のコードをシンプルにするため |
| kaminari | 不採用 | ページネーションを使うほど閲覧画面が長くならないため |

- 今回チャレンジしたい点：商用辞書アプリと遜色ないSPのユーザーインターフェイスを目指します。
- 不安な点：日本語の1文字検索はインデックスの選択性が低く、全件スキャンになりやすい。今回は辞書アプリのデータ規模が数百〜数千件程度と想定されるため、全件スキャンでも許容範囲の速度が出ると考えている。もし速度が問題になった場合は、1文字検索時のみ前方一致（ LIKE 'あ%' ）に絞るなどの対処を検討します。

---

### 10-3.キャッチアップ不足の懸念

検索機能はRansackの部分一致を用いて実装する。見出し語・意味/作例・季節・作成者のいずれもRansackの標準機能でカバー可能であり、技術的な懸念点は特にありません。将来的に検索精度を高める場合はpg_searchなどのgemを導入することを検討します。
